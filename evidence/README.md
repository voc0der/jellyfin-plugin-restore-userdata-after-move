# Jellyfin detached user-data probe

Artifacts behind [§17 of DESIGN.md](../DESIGN.md#17-empirical-results). Run
2026-08-12 against Jellyfin 10.11.11 and 12.0-rc5.

The probe is a disposable plugin: one `IScheduledTask` with no default triggers
that constructor-injects `IDbContextFactory<JellyfinDbContext>`, projects every
`UserData` row with `AsNoTracking()`, and logs them. It performs no writes.

This is a historical artifact, kept so the §17 results can be reproduced. It is
not the plugin being built, and its GUID (`b7e4c1a2-…`) is not the plugin's —
see the identity table in [DESIGN.md §5](../DESIGN.md#5-plugin-shape-and-dependencies).

## Contents

```
src/Gate0.csproj        plugin project, pinned to Jellyfin 10.11.11 / net9.0
src/rc5.patch           retargets Gate0.csproj and meta.json at 12.0.0-rc5 / net10.0
src/Plugin.cs           BasePlugin registration
src/Gate0Task.cs        the scheduled task
src/meta.json           plugin manifest (targetAbi 10.11.11.0)
results/jellyfin-10.11.11.log    filtered server log: probe output, item removals, scans
results/jellyfin-12.0-rc5.log    filtered server log: probe output, plugin load
results/userdata-rows-by-run.txt every UserData row at each of the 10 probe runs
```

Deliberately excluded: build output, server data directories, access tokens, and
the generated MP4 fixtures (1-second `lavfi` black frames, regenerated by the
commands below). Absolute paths in the logs are collapsed to `<SCRATCH>`.

## Environment

Docker was unavailable, so servers were run from the official self-contained
tarballs rather than images:

```sh
curl -LO https://repo.jellyfin.org/files/server/linux/latest-stable/amd64/jellyfin_10.11.11-amd64.tar.gz
curl -LO https://repo.jellyfin.org/files/server/linux/latest-preview/amd64/jellyfin_12.0-rc5-amd64.tar.gz
tar xzf jellyfin_10.11.11-amd64.tar.gz

./jellyfin --datadir  $S/srv/data   --configdir $S/srv/config \
           --cachedir $S/srv/cache  --logdir    $S/srv/log
```

`Jellyfin.Controller` and `Jellyfin.Database.Implementations` are both on
nuget.org at `10.11.11` and `12.0.0-rc5`. Host packages are referenced with
`ExcludeAssets=runtime`; only the plugin's own assembly is installed.

## Build and install

For 10.11.11:

```sh
dotnet build -c Release
mkdir -p $S/srv/data/plugins/Gate0_1.0.0.0
cp bin/Release/net9.0/Jellyfin.Plugin.Gate0.dll src/meta.json \
   $S/srv/data/plugins/Gate0_1.0.0.0/
```

For 12.0 RC5, apply the patch first — it retargets both the project and the
manifest, so no manual edits are needed:

```sh
patch -p1 < src/rc5.patch          # from this directory
dotnet build -c Release
mkdir -p $S/srv/data/plugins/Gate0_1.0.0.0
cp bin/Release/net10.0/Jellyfin.Plugin.Gate0.dll src/meta.json \
   $S/srv/data/plugins/Gate0_1.0.0.0/
```

## Driving the server

Setup wizard, then authenticate. Note the header form — 12.0 RC5 rejects
`X-Emby-Token` and `?api_key=` with 401:

```sh
B=http://127.0.0.1:8096
curl -sX POST "$B/Startup/Configuration" -H 'Content-Type: application/json' \
  -d '{"UICulture":"en-US","MetadataCountryCode":"US","PreferredMetadataLanguage":"en"}'
curl -s "$B/Startup/User" -o /dev/null
curl -sX POST "$B/Startup/User" -H 'Content-Type: application/json' \
  -d '{"Name":"admin","Password":"<pw>"}'
curl -sX POST "$B/Startup/Complete"

TOKEN=$(curl -sX POST "$B/Users/AuthenticateByName" \
  -H 'Content-Type: application/json' \
  -H 'Authorization: MediaBrowser Client="gate0", Device="probe", DeviceId="gate0probe", Version="1.0.0"' \
  -d '{"Username":"admin","Pw":"<pw>"}' | jq -r .AccessToken)
A="Authorization: MediaBrowser Token=\"$TOKEN\""
```

Libraries span both tiers, mirroring a pre-tree Coldarr install. Internet
providers are disabled so provider IDs come only from local NFO:

```sh
curl -sX POST "$B/Library/VirtualFolders?name=Movies&collectionType=movies&refreshLibrary=false" \
  -H "$A" -H 'Content-Type: application/json' -d '{"LibraryOptions":{
    "PathInfos":[{"Path":"'$S'/media/hot/movies"},{"Path":"'$S'/media/cold/movies"}],
    "EnableRealtimeMonitor":false,"SaveLocalMetadata":false,"EnableInternetProviders":false,
    "TypeOptions":[{"Type":"Movie","MetadataFetchers":[],"MetadataFetcherOrder":[],
                    "ImageFetchers":[],"ImageFetcherOrder":[]}]}}'
```

Fixtures:

```sh
ffmpeg -f lavfi -i color=c=black:s=32x32:d=1 -c:v libx264 -pix_fmt yuv420p \
  "$S/media/hot/movies/Test Movie (2020)/Test Movie (2020).mp4"
# movie.nfo carries <uniqueid type="tmdb">603</uniqueid> and
# <uniqueid type="imdb" default="true">tt0133093</uniqueid>
```

Trigger a scan or the probe by task id from `GET /ScheduledTasks`:

```sh
curl -sX POST "$B/ScheduledTasks/Running/<id>" -H "$A"
```

## Sequence that produced the results

1. Scan; confirm one movie and one episode exist with provider IDs from NFO.
2. Create a second user; set distinct played / favorite / rating state for each.
3. Probe — baseline live rows (run 3 in `userdata-rows-by-run.txt`).
4. Relocation 1: `hot/movies/Test Movie (2020)` → `cold/movies/…`, crossing a
   configured location. Scan.
5. Removal does not occur while the vacated root is empty. Add an unrelated file
   to that root, scan again; the old item is then removed and its rows detach.
6. Probe — six detached rows, new item carries none.
7. Write played / favorite / rating onto the new item for both users while the
   sentinel rows are present. Probe — live and detached rows coexist for the same
   `(UserId, CustomDataKey)`, differing only by `ItemId`.
8. Relocation 2: rename inside `cold/movies`. Scan.
9. Relocation 3: `cold/movies/…[v2]` → `hot/movies/…[v3]`. Scan.
10. Relocation 4, the discriminating one: a previously unused title with
    `tmdb 550` / `imdb tt0137523`, no detached rows for either key, both roots
    kept populated, renamed inside `cold/movies`, and exactly one scan — which
    removed the old item and created the new one in the same pass.

Relocations 1–3 vary root-crossing and prior-detached-state together. Relocation
4 separates them; see §17.7.

## Reading the row dumps

`userdata-rows-by-run.txt` holds all ten probe runs in order. Item and user IDs
are truncated to eight characters. `item=00000000` is the sentinel
`00000000-0000-0000-0000-000000000001`, i.e. a detached row.

Mapping of runs to the sequence above: run 3 is step 3, run 5 is step 6, run 6 is
step 7, run 7 is step 8, runs 8–9 are step 9, and the last two runs bracket
step 10.
