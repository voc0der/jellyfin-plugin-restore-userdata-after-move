Restore User Data After Move

When a file's path changes, Jellyfin replaces the item and leaves the old item's played state, resume position, favourite and rating behind as unreachable rows. This plugin finds those rows and works out which current item each one belongs to.

This build analyses only. It contains no task that can change Jellyfin user data. It writes a plan file you can review; nothing consumes it.

Eligible libraries

Only items in these libraries can be recovery targets. Nothing is analysed until at least one is selected.

Final path prefixes

One absolute path per line. A target must sit beneath one of these to be recovered. Comparison is path-component aware, so /data/library/tv2 is not beneath /data/library/tv.

Options

Turn this off only if the library lives on storage that is deliberately offline while you analyse.
The plan file always contains the full detail. This only adds it to the server log, which includes titles and user IDs.
Older plan files are deleted after each run.

Running the analysis

Finish moving your files and let Jellyfin complete a full scan first, so the old items are gone and the new ones exist. Then run Analyze detached user data from Dashboard → Scheduled Tasks. It has no schedule and never will; run it by hand.

The task reports counts per outcome and writes a plan under the plugin's data folder. A high "no match" or "ambiguous" count is a real answer about your library, not a failure.
